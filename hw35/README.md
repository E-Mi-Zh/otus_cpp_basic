# Домашнее задание №9 «Распареллеливание программы»

## Цель

Переписать однопоточную программу, которая подсчитывает самые частые слова в
файлах так, чтобы она получила выигрыш от использования нескольких потоков.

## Исходная реализация

[topk_words.cpp](./topk_words.cpp) печатает 10 самых частых слов, которые
встретились во всех входных файлах и печатает время своей работы в миллисекундах.
При подсчете слов регистр не учитывается, различные знаки препинания не
игнорируются, а являются частью слова (любая непробельная последовательность
символов).

Использует один поток для подсчёта слов. Дана в задании готовой.

## Параллельная версия 1 (общий словарь)

[topk_words_par1.cpp](./topk_words_par1.cpp) - в этой версии создаётся по одному
потоку на файл. Потоки используют один и тот же словарь, защищённый мьютексом.

## Параллельная версия 2 (отдельные словари на поток)

[topk_words_par2.cpp](./topk_words_par2.cpp) - каждый поток пишет частоты слов в
свой отдельный словарь, которые потом объединяются.

## Проверка

Для тестирования использовался текст книги [Великий Гетсби](https://www.gutenberg.org/files/64317/64317-0.txt).
3 самых частых слова в этом тексте:
* the
* and
* a

На вход подавалось 10 копий одного и того же файла, по 30 раз:

```bash
$ for i in `seq 30`
> do
> ./topk_words_single ../64317-0.txt ../64317-1.txt ../64317-2.txt ../64317-3.txt ../64317-4.txt ../64317-5.txt ../64317-6.txt ../64317-7.txt ../64317-8.txt ../64317-9.txt | grep Elapsed
> done
```

Результаты приведены в таблице:

| Программа         | Среднее время, мкс | Дисперсия, мкс |
| ----------------- | ------------------ | -------------- |
| topk_words_single | 418872             | 4634           |
| topk_words_par1   | 933884             | 26066          |
| topk_words_par2   | 179442             | 3378           |

## Результаты

Быстрее всего оказалась версия 2, с отдельным словарём на каждый поток, т.к. они
смогли писать в него независимо и не стоять в блокировках за общий ресурс, как в
версии 1.

Версия 1 имела бы право на жизнь, если бы функция подсчёта была сложнее и допускала
работу потоков, пока они ждали ресурс. И при этом накладные расходы на отдельные
ресурсы (словари) для потоков были бы велики...
